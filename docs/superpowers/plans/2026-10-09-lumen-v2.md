# LUMEN V2 implementation plan

User brief: independent privacy-first metasearch platform, one feature branch and PR. Reuse Next.js components, implement official Python source adapters, IndexedDB workspaces, local profiles and comparison. No SearXNG runtime, no required paid key, no query logging or invented metrics.

## Design and contracts
- `frontend/`: migrated Next.js app, same-origin API forwarding to fixed `LUMEN_BACKEND_URL`.
- `backend/app/`: Pydantic query/results, injectable engine registry, async orchestration, URL canonicalization, deterministic ranking, bounded cache, FastAPI routes.
- Keyless Wikipedia, GitHub, Crossref, Hacker News, Commons; optional Brave web only. Categories general, developer, science, news, images; videos/maps/files unavailable unless supported.
- Backend API `/api/v1/{health,search,engines,categories,diagnostics}`, POST `/api/v1/search/compare`.
- SearchQuery: q, category, engines (CSV at HTTP boundary/list in model), language, time_range (none/day/week/month/year), safe_search 0..2, page 1..20, limit 1..50, site/exclude_site lists (CSV HTTP), file_type optional, ranking (balanced/relevance/recency), preferred_domains list.
- SearchResult: id,title,url,domain,snippet,category,source_engines[],published_at?,thumbnail_url?,score,rank,metadata{},ranking_explanation{}.
- SearchResponse: query,results,result_count,category,page,limit,has_more,timing_ms,engine_status[] (engine,status,latency_ms,message?),partial,cached,applied_filters{},suggestions[]. Unknown totals omitted.
- Engine metadata: id,name,categories[],requires_auth,configured,enabled,filters[],rate_limit_per_minute.
- Compare request {q,left:{engines:[...]},right:{engines:[...]}}; response {left:SearchResponse,right:SearchResponse,shared:[canonical URL],left_only:[],right_only:[],overlap:number}.
- Diagnostic metrics aggregate only, protected token configured server-side; inaccessible if unset.
- Unsupported upstream filters reported as capabilities; local domain/time/file filters explicitly labeled.

## Work packages and validation
1. Core backend + API: test-first query, URL normalization, deterministic ranking, cache identity/bounds, partial failure/cancellation, rate limits and API privacy checks. pytest, Ruff, mypy.
2. Adapters: official endpoints with bounded HTTP, safe normalization, malformed data/429 tests. Separate live smoke verification.
3. Search frontend: typed backend contracts, URL filter state, capability categories, rich results, abort stale requests, comparison and profiles.
4. IndexedDB research: validated import/export, collections/tags/notes/move/delete, optional history default off, keyboard/accessibility; fixture E2E.
5. Infrastructure: two non-root Docker services, healthchecks, CI, docs and migration; no old runtime references.
6. Integrate, review full diff, execute all checks, capture real screenshots, measure fixture benchmark and live smoke separately, commit logically, push feature branch and open PR without merge.

No review/clarification gate: the user explicitly directs independent decisions and end-to-end execution. Existing cloud checkout provides isolation. Network access blockers are reported and required domains saved; credentials never requested in chat.
